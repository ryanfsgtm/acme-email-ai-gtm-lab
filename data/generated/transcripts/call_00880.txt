Eva Boehm (Privacy): The customer data platform, the web application, and a service system. We have customer profiles, product usage, and support interactions. Priya Shah (Account Executive): We can define a primary profile key and document which fields are eligible for matching. For sensitive attributes, we can restrict ingestion or keep them in the source system and use an approved flag instead. The exact design needs your data architect.

Eva Boehm (Privacy): Better. We have a large organization, about seven hundred forty-four employees, and not all of them will use the system. Access should be based on job function and removed promptly when someone changes roles.

Eva Boehm (Privacy): They provide SSO. Automated deprovisioning is available for some applications, but I need to confirm whether this one would be included. If it remains a manual ticket, we need a compensating review.

Eva Boehm (Privacy): It varies. Web forms record timestamp and language. Some partner referrals come with contract language. Existing customers may receive service messages that are not marketing, and people confuse the two. We need distinct purposes and a way to preserve the original evidence.

Priya Shah (Account Executive): We can map consent purpose, source, timestamp, and status as separate fields, then use purpose-specific rules in audience creation. Would privacy require the original form payload to remain available?

Eva Boehm (Privacy): Usually yes, or at least a durable reference to it. A status of “opted in” without provenance is not enough when someone asks why they were contacted.

Priya Shah (Account Executive): Understood. We can keep the source reference in the profile and retain the raw evidence in the system of record, subject to your retention policy. I’ll have our privacy specialist confirm the audit behavior and export format.

Eva Boehm (Privacy): What happens when someone withdraws consent?

Priya Shah (Account Executive): The suppression or opt-out state should be honored by downstream campaigns. We need to determine which system is authoritative and how quickly updates propagate. In the demo environment, I can show the rule; I don’t want to promise a real-time guarantee before integration testing.

Eva Boehm (Privacy): That distinction matters. A delayed suppression could create an incident, especially if a campaign has been queued.

Priya Shah (Account Executive): Agreed. We’ll test withdrawal, queued messages, retries, and failure handling. We should also test a record with multiple communication purposes so a service notification is not accidentally treated as promotional permission.

Eva Boehm (Privacy): Add household-level preferences. One person may share an address with another customer, and an email-level suppression is not always the same as an account-level rule.
