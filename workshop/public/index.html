Begin with the prerequisite checks and tell me only the next action I need to take.

Interrogate · 5 minMake uncertainty visible

Ask the answer to prove itself

Coverage, traceability, and failures turn “sounds right” into something we can evaluate.

Audit the answer you just gave me. Do not perform a new analysis yet.

Report:
1. Exactly how many Attio transcript notes exist and exactly how many you analyzed.
2. How you handled pagination and whether you retrieved every page.
3. Any records that failed, were skipped, sampled, or truncated.
4. A transcript ID and verbatim evidence span supporting every major claim.
5. Whether another run would produce the same result.

Separate facts you can prove from assumptions. If complete coverage cannot be demonstrated with a machine-readable manifest, say so plainly.
Build · 25 minCore exercise

Build the system, not the summary

This is the shift: use the coding agent to create a durable analysis pipeline whose output can be checked.

Build a reliable, resumable system that analyzes every ACME Email call transcript in Attio.

Before changing code, inspect the repository and propose a short implementation plan. Then implement it.

The system must:
- Read through the Attio API, including every page of transcript Notes.
- Treat Attio as the source of truth; do not analyze the local transcript folder as a shortcut.
- Cache normalized source records locally without storing or printing the API key.
- Create a machine-readable inventory proving expected, retrieved, processed, failed, and skipped counts.
- Analyze calls in bounded batches using the configured coding-agent/model loop at low reasoning effort.
- Save structured per-call observations and checkpoints so interrupted runs resume without repeating completed work.
- Preserve account, opportunity, call type, date, speaker, transcript ID, and exact evidence spans.
- Separate customer statements from seller-introduced topics.
- Aggregate common themes without hiding rare but commercially important signals or counterexamples.
- Validate every citation against its source transcript.
- Produce a leadership report with coverage, methodology, findings, segment and time comparisons, minority signals, limitations, and linked evidence.
- Never claim complete coverage unless validation proves it.
- Keep all CRM writes in dry-run mode unless I explicitly approve them.

Run tests and validation. Show progress as you work. Stop and explain if a requirement cannot be satisfied.
Verify · 10 minTrust, then verify

Pressure-test the result

A good system makes it easy for another agent—or teammate—to challenge its claims.

Act as a skeptical reviewer of the analysis system and final report.

Independently verify:
- source inventory equals the live Attio corpus,
- every source reached a terminal processed or explicit failure state,
- checkpoints can resume safely,
- citations are verbatim and point to the correct transcript and speaker,
- aggregate claims are supported by cited observations,
- rare findings are not single unsupported anecdotes,
- seller language is not misattributed to customers,
- no API key or sensitive configuration appears in artifacts,
- a second run is deterministic or clearly explains expected variation.

Produce a pass/fail table. Fix implementation defects you find, rerun only the affected stages, and update the report. Do not soften failed checks.
